X4 舰船制作工具

仅处理 L / XL 舰船（M / S 结构差异大，不处理）。新增：复制现有舰船作模板、生成新舰船；修改：直接改已有舰船属性与名称。模型、材质、挂载结构一律不触碰（⑧ 可调挂载点 tags 以限定可装装备）；模板数据源为现有 X4 舰船 mod。

⑤-1 材质参数（material_library.xml，调整船体着色）

读取本船 component 中 <material ref="collection.material"/> 引用的材质，列出材质库（material_library.xml）里各参数当前值（输入框占位符），填新值即覆盖： 本 mod 自带材质直接改 extensions\<mod>\libraries\material_library.xml；原版/其他 mod 的材质在该文件用 diff <replace …/@value> 覆盖（不改游戏本体）。 换用新材质名：修改模式=就地重命名材质定义，本 mod 内所有引用一并更新（共用船一起变）；新增模式=克隆为独立副本，仅新船换用，不动原材质。参数调整始终作用于改名后的最终名字。所有栏留空 = 不改；只影响外观，不影响任何战斗数值。

⑥ AI 派系使用（jobs，让 AI 主动开这艘船）

勾选派系后，ship 会归属这些派系（wares 多 owner），并生成 jobs 让派系舰队在巡逻/守卫/攻击时使用该船。不勾选则只有玩家/造船厂能造，AI 不会主动开它。
选择派系（可多选）
任务类型（可多选）

⑥-1 shipgroup 归属（舰船分组，AI 调度候选）

shipgroup 决定该船会被哪些派系的 AI 通过 <select> 调度选中：jobs 只声明"某派系某尺寸需要船"，具体由 shipgroups 的分组 + 权重加权随机挑选。 启用后按下方分组列表写入目标 mod 的 shipgroups.xml：分组名已存在 → 在该 <group name="X"> 下新增该船的 <select> 引用；不存在 → 新建该 <group>。一艘船可加入多个分组（与整船一并保存）。
目标分组（可多个，默认=当前已属分组）

勾选「默认预装」= 造船时自带（default）；不勾选 = 该船可装（compatible）。

⑧ 挂载点 tags（按组指定，写回 component）

挂载点 tags：component 里每个连接点（connection）的 tags 决定该槽能装哪些装备（装备 tags ⊆ 槽 tags 才可装）。 工具读取该船 component 的挂载点，按「连接组 + 尺寸」聚合为块（同组且同尺寸才合并为一个设置栏），方便统一指定 tags；无组的连接点逐槽设置。写回 component（改前备份）。 某组/某槽留空 = 删除其 tags（恢复全槽默认匹配）。tags 为空格分隔的自由文本。 尺寸备忘：组件尺寸由挂载点名中的 _es- / _s- / _m- / _l- / _xl- / _exl- 区分 （如 g_bot_01-up7con_shield_m-001 即 M 尺寸；名字无尺寸字符时按 tags 的 small / medium / large / extralarge 兜底识别）。

⑧-1 macro 连接点（connections，写回 ship macro）

对应规则：模型工具导出的 component（舰船 XML）定义连接点本体（name / tags / 位置），ship macro 的 connections 是对其的加工—— <connection ref="组件连接点名"> 引用组件连接点，内挂 <macro ref="功能宏" connection="入口连接"/> 挂载部件 （bridge 驾驶舱 / storage 货舱 / dockarea 船坞 / dock 停机坪 / buildmodule 载具坞 / launchtube 弹射管）。内挂宏留空 = 纯转发该连接点。 ref 必须存在于本船组件，否则为悬空引用（游戏静默忽略、功能失效，提交时拦截）； 内挂宏的入口 connection 必须是该宏实测存在的入口（同名宏各族不同：boron bridge 是 con_cockpit_01、argon 是 con_cockpit）， 写错同样被静默忽略、功能失效（典型症状：不能指派船长、船不能操控、登船无舰桥），提交时一并拦截；标红行即上述两类问题。 占位符：{STORAGE}=本船货舱宏，{DOCKAREA}=本船船坞宏（生成/修改时自动代入实际宏名）。
连接行（行序即写出顺序）

⑨ 装配预设（可选，生成 loadout）

连接组（group）统一装备：护盾和炮台按连接组挂载——同一组且同尺寸的连接点统一装同一种装备（官方用 <shields/turrets ... group="组名" exact="数量">）。因此工具把护盾/炮台按「组 + 尺寸」聚合为块： 每块一个装备选择 + 组名（含尺寸）+ 下辖同组同尺寸所有连接点 id（悬停看全），块内统一选一种；同组不同尺寸会拆成多个设置栏，可分别选装备。 无组的连接点、以及引擎/主武器（无组批量语法）按逐插槽生成（path="连接点id"，自动加 ../ 前缀）。 尺寸备忘：组件尺寸由挂载点名中的 _es- / _s- / _m- / _l- / _xl- / _exl- 区分 （如 g_bot_01-up7con_shield_m-001 即 M 尺寸；名字无尺寸字符时按 tags 的 small / medium / large / extralarge 兜底识别）。
optional（可选装备）：勾选后该装备为可选，AI / 船厂生成舰船时可能随机不装（用于生成多样性）； 不勾 = 必装。引擎/推进器必装，护盾/炮台/主武器可按需勾选。
引擎 engine（可多槽）
护盾 shield（可多槽）
炮台 turret（可多槽）
主武器 weapon（可选）
推进器 thruster（可选，virtualmacros）

游戏解包（XRCatTool 自动解包基游戏 / DLC / mod）

调用官方 X Tools 的 XRCatTool.exe 解包 cat/dat：基游戏解到输出根目录，mod 解到 <输出>\extensions\<mod名>（mod 的 subst_* 覆盖包解到输出根，符合游戏加载语义）。轻量模式只解 xml/文本（索引、库、t 文本、脚本；本工具全部功能够用，体积小速度快）；完整模式连模型贴图一起解（约 20GB+，仅 Blender 需要原版模型时用）。务必解到全新目录，不覆盖当前工程数据。
