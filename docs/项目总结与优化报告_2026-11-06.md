# EVE_Ship_Builder 项目总结与工程优化报告

日期：2026-11-06　范围：`server.py`（8463 行）、`index.html`（4019 行）、`x4_lookup.py` 及其余脚本
结论先行：**功能已覆盖完整，问题不在功能缺失，而在“同一条规则被实现了 3～5 遍”，导致每次事故只能逐点修补。**

---

## 一、项目定位与功能地图

本地单页工具，读取 X4 解包根，把现有舰船 / 装备 / 效果资产复制改名后写入目标 mod，并完成游戏所需的全部注册。

| 域 | 选项卡 | 主要能力 |
|---|---|---|
| 舰船 | 舰船模块 | 新增/修改、属性、挂载点 tags、装配预设、jobs、shipgroups、软件、材质调参、建造成本、t 文本 |
| 装备 | 炮台 / 主武器 / 护盾 / 引擎 | 新增/修改、引用链、模型复用（原版指向 / mod 复制）、tags、插槽尺寸、价格材料、图标别名、护盾视觉 |
| 弹药 | 弹药（弹丸 / 导弹） | 弹丸与导弹宏、弹丸特效（impact/bigobjectimpact/launch）、尾焰、爆炸、光束/视觉材质 |
| 复用 | Dock 复用 / 模型同步 | 原版 dock 组件改名注册 + waypoint 替换；EGO 导出目录回填舰船模型；组件装配（缩放复用） |
| 辅助 | 解包 / Diff 工具 | XRCatTool 解包、diff 校验与预览、XSD 枚举、列表刷新、删除物品 |

配套：`docs/MAINTENANCE.md`（事故日志）、`docs/BLENDER_组件缩放导出需求.md`（外包给 Blender 对话的契约）。

**当前规模**：后端 50 个 GET 分支 + 24 个 POST 分支；前端 10 个选项卡、92 个行内 `onclick`、80 处 `fetch`、36 个顶层全局变量、28 处直接 `localStorage`。

## 二、实现方式现状

### 2.1 后端是一个“大文件 + 多层混杂”

同一个 `server.py` 里同时存在五个层次：

1. HTTP 层：`H.do_GET`（L7704-8007）/ `H.do_POST`（L8008-8114）
2. 业务管线：`generate`（L1947）、`equip_generate`（L5518）、`bullet_generate`（L5812）、`ship_model_sync`（L595）、`component_assemble`（L779）、`dock_clone`（L1156）
3. XML 文本补丁：大量 `re.sub` 直接改属性
4. 资产搬运：`shutil.copytree` / `_copy_dir_rename` / `_copy_rename_asset`
5. 注册与缓存：index / wares / t / icons / jobs / shipgroups + 三层缓存

没有模块边界，规则靠注释和事故记忆维持。

### 2.2 前端是“两个表单引擎 + 若干独立小页面”

- 舰船：`collect` / `restoreFields` / `restoreCost` / `restoreJobs` / `restoreLoadout` / `stashDraft`（L2417-2560）
- 装备：`eqCollect` 系 / `EQ_FIELDS` / `stashEq` / `unstashEq`（L3719-3800）
- 其余页面各自一套：`mi*`（模型同步）、`dk*`（Dock）、`up*`（解包）、diff 工具

装备 5 类共用一套 `cls` 参数化引擎（这部分设计是好的）；舰船与装备之间没有共享。

### B. 边界不清

- **B1 缓存分三层但无统一契约**：磁盘签名缓存（`_cached_whole` L1460）、约 20 个模块级全局缓存、按来源增量缓存（`eq_cache_refresh_source` / `bullet_cache_refresh_source`）。`_refresh_soft`（L7644）逐个手工置 `None`，新增缓存变量极易漏掉；`refresh_caches`（L7667）又是另一套全量清理。
- **B2 “读组件文本”有两个入口**：`_read_comp_txt`（L3135，会应用 diff 补丁）与 81 处直接 `open(...).read()`。哪些场景必须走 diff 合并没有结论，属于隐性规则。
- **B3 校验与写入交错**：`generate` 先复制 data 目录、再校验 component XML（L1994-2029），校验失败已产生半成品；`equip_generate` 在末尾追加尾焰/爆炸，失败直接 `return`，此前文件已落盘。
- **B4 `.jcs` 策略三套**：舰船流禁用（L2003）、`_copy_dir_rename` 禁用（L5183）、组件流保留（L849-850）。注释说明了原因，但规则没有单点声明，容易被下一次“顺手统一”改坏。

### C. 局部规则过多（硬编码）

`_x\d+` 缩放后缀（L860）、`_up` / `_up7` 后缀、`7777771` t 页、`upgrade_<宏>_macro` 图标命名、`ego_dlc_` 只读判断（多处）、`ship_` / `storage_` 前缀推导、dockarea 名字用 `rsplit` 拼（L2047-2049）、`UP7_EVE_battleship_*` group 名（L3768）、`"1/true/yes/on"` 布尔解析。

这些规则都对，但散落在 10 余个函数里。x150 事故的修复之所以反复，就是因为“命名约定”和“路径归属”没有单一出处。

### D. 工程卫生

- `x4_wp_export.py` 已明确不再维护，仍在根目录（README 也这么说）。
- 根目录 4 个 `*_test.py` / `*_test.py` 无统一 runner；`tools/` 下 16 个历史脚本混放（含调试补丁）。
- README 仍写“server.py 约 2600 行、index.html 约 1700 行”，接口表只覆盖一部分；实际 98 个端点。
- `docs/MAINTENANCE.md` 已 23 KB，按事故追加，缺少“规则索引”（每条铁律在哪、由哪个函数保证）。

## 四、优化路线（保持功能不变）

按“收益 / 风险”排序，**每一阶段都可独立上线、独立回滚**。

### P0 止血型收敛（低风险，直接消灭已知事故类型）

1. **geometry 单一函数**：`resolve_geometry(mod, rel_dir, comp_id, has_own_data) -> str`，4 个调用点全部改为调用它；同时把“原版共享 / mod 自有”判定显式化。
2. **装备字段表单一数据源**：`EQUIP_FIELDS[cls] = [(key, tag, attr, kind)]`，读、写共用；预计减少 ~200 行。
3. **特效写入抽一个**：`ensure_effect_entry(mod, lib_file, name, block)` + `finish_write(mod, files)`，6 处收敛为 1 处实现 + 6 个调用。
4. **HTTP 层薄封装**：`_json(obj)` + `_q(name)`，先把样板降下来，不改任何业务逻辑。

### P1 边界统一（中风险，需要回归验证）

5. **index 注册统一**：单一 `register_assets(mod, items)`，路径统一“相对 assets”，四套实现收为一套。
6. **写入事务化**：`begin() → write → verify → commit`，失败按 `created` 逆序回滚；至少做到“校验在落盘前”。
7. **缓存失效分组**：所有全局缓存登记进一张表（名称 → 失效组），`_refresh_soft` 按组失效，杜绝漏项。

### P2 结构分层（较大，建议功能冻结窗口做）

8. `server.py` 拆为：`http_app.py` / `assets.py`（路径与复制）/ `xmlpatch.py` / `ship.py` / `equip.py` / `effects.py` / `dock.py` / `cache.py`。接口契约不变，前端零改动。
9. 前端收敛：`api()` 统一请求封装、`toast()` 统一状态、`pickDir()` 统一目录选择、`stash()` 统一暂存；舰船/装备表单引擎合并留到最后。

### P3 护栏与文档（随时可做）

10. `docs/RULES.md`：geometry 归属、jcs 策略、命名约定、t 页、注册链路、图标链路六条铁律，代码注释引用编号。
11. 建 `tests/` + 一个 `run_tests.ps1`：至少覆盖 geometry 解析、字段读写往返、index 注册、dock waypoint 校验、组件装配冒烟。
12. 归档 `x4_wp_export.py` 与 `tools/` 历史脚本；README 数字与接口表按实际更新。

## 六、已确认的执行顺序

每步独立可跑、独立回滚；后一步依赖前一步的收敛结果。全程不改前端、不改接口契约、不改发布包白名单。

| 步骤 | 内容 | 主要落点 |
|---|---|---|
| 0 | 测试护栏：`tests/` + `run_tests.ps1`（unittest，不启动服务） | 新增 |
| 1 | geometry 规则单点化：`geo_owned()` / `geo_rebase()`，dockarea 共享改为显式分支 | 组件装配 L829、`_copy_rename_asset` L5488、generate L2016、dockarea L2066 |

| 3 | 特效写入收敛 `upsert_effect()` + `finish_write()`；去掉 `except: pass` | L6258、L6423、L6618、L6764、L6882、L7024 |
| 4 | HTTP 薄封装 `_json()` / `_q()` / `_body()` | L7704-8114 |
