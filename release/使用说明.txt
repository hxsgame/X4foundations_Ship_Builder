X4: Foundations 舰船 Mod 辅助工具
=====================================

【环境要求】
Windows 10/11  +  Python 3.9 或更高版本
安装 Python 时务必勾选 "Add Python to PATH"。
本工具只用 Python 标准库，不需要 pip 安装任何依赖。

【启动】
1. 把压缩包解压到任意目录（路径含中文也可以）。
2. 双击 server.py（如果没反应，右键 → 打开方式 → Python；或命令行运行 python server.py）。
3. 稍等片刻，浏览器会自动打开 http://127.0.0.1:8765（首次启动预热较慢属正常）。
4. 关闭黑色命令行窗口即停止服务；重复双击不会重复启动，会直接打开已有页面。

【首次使用（重要）】
1. 打开页面顶部「游戏解包」选项卡。
2. 在「当前解包根」填写你的 X4 游戏解包目录（含 assets、index、libraries 等文件夹的那一层）。
3. 保存设置，然后关闭窗口、重新启动 server.py 使配置生效。
4. 之后在各功能选项卡里选择「目标 mod」目录即可开始使用。

一、主要功能
--------------------------------------------------
1. 舰船模块
   修改现有舰船数据；以现有舰船为模板，一键生成新舰船的全套 XML（包括：舰船宏、storage 宏、wares、shipgroups、t 名称、index 注册。新 id 自动追加 _up）。
2. 装备编辑
   修改已有装备/弹药/尾焰/爆炸的数值与引用，写入前自动备份。
3. Dock 复用
   复用现有 dock 的模型，只改 XML：waypoint 段整体替换，dockingbay 连接只按 name 修改 group（含清空组名），几何 _data 指向原版不动。
4. 模型同步
   把 Blender 导出的船模同步进目标 mod（详见第二节）。
5. 游戏解包 / Diff
   解包游戏与 mod 数据、对比两份文件差异、复制替换文件。

--------------------------------------------------
二、与 Blender 插件、XML 补全脚本的关系（重点）
--------------------------------------------------
本工具不建模、不生成网格，它负责“把 ego Blender Tools导出的Blender资产接进游戏 mod”。
整条链路如下：

  A. 本工具配套的 Blender 插件（X4_blender42_add_components_fixed_addon.py，组件/硬点/waypoints编辑插件，需在blender安装）：在 Blender 里摆放硬点、组件连接点、waypoint、dockingbay等。

   B. 通过ego  Blender Tools 插件，把改好的模型导出为 XML（舰船 XML）。

   C. 本工具
     配置“模型同步”选项卡，指定各个路径，点击“开始同步”，工具会自动完成以下 D、E步骤。（其中“③ 外部 py 工具（处理舰船 xml）”路径即X4_BlenToolOut_con_ImproveTool_easy_fixed.py所在的文件路径。“⑤ 可覆盖文件结构导出路径”是个副本路径，用来生成带文件结构的修改内容副本，方便在备份目录修改时向真实游戏目录覆盖生效）。

  D. 自动从egotools导出目录（X:\...\Destination\p1data\...）获取舰船资源（xml、data等）

  E. 自动用配套舰船 XML 补全脚本（X4_BlenToolOut_con_ImproveTool_easy_fixed.py）专门处理 egotools Blender 导出的组件 XML：补全硬点对应的连接宏引用、生成左右镜像连接、同名连接去重、连接布局规范化、清理 waypoint。

  ▲ 典型链路 1：新舰船 / 换船模
    Blender 编辑模型与硬点
      → 插件导出（保持 EGO 导出目录结构：assets/units/size_*/舰船id.xml
         + 舰船id_data/ + 可选 _data.ani / _data.dae）
      → 本工具「模型同步」：填 舰船 id、资源路径（导出目录）、
        补全脚本路径、修改路径（目标 mod）
      → 工具自动依次完成：
         ① 备份目标文件（mod 内 _shipmodel_backup，保留最近 3 次）
         ② 清空补全脚本目录下的 xml，并把导出的组件 xml 复制进去
         ③ 调用补全脚本运行（补全连接点、镜像、规范化）
         ④ 把 ref+macro 形式的连接点从组件 xml 剪切进舰船宏
         ⑤ 写入组件 xml 与舰船宏，整目录替换 舰船id_data
         ⑥ 复制 _data.ani / _data.dae（有则复制）
         ⑦ 在 moding/ 下生成可直接覆盖的目录结构
     前提：目标 mod 里必须已存在该 id 的舰船宏（先在「舰船模块」新增该舰船）。

  ▲ 典型链路 2：Dock 复用（不改模型，只改 XML）
    Blender 里摆好 waypoint 与 dockingbay 连接点
      → 插件导出 waypoints.xml（<waypoints> + <connections> 两段）
      → 本工具「Dock 复用」：选 dock 模板 + 填新 id + 选该 xml（waypoints.xml）
      → 生成副本：waypoint 整体替换、dockingbay 按 name 只改 group，
        复制宏并写入 index 注册，几何仍指向原版模型

  ▲ 不需要 Blender 的功能
    「舰船模块」新增舰船（模板生成）、「装备编辑」改数值、
    「游戏解包 / Diff」，都只处理 XML，可直接使用。

【安全说明】
- 服务只监听本机 127.0.0.1，不对外网开放，不需要联网。
- 覆盖宏/组件前会自动备份到「解包根\_x4sb_backup」（可在配置中改路径）；
  模型同步另备份到 mod 内 _shipmodel_backup，只保留最近 3 次。
- 所有配置保存在工具目录下的 builder_config.json，仅本机有效。
- 新 id 自动追加的后缀可在 builder_config.json 里用 id_suffix 修改（默认 _up）。
- 若备份失败，工具会中止写入，不会覆盖原文件。

【常见问题】
- 双击 server.py 没反应：右键 → 打开方式 → Python，或命令行运行 py server.py；提示未检测到 Python 则重新安装并勾选 Add to PATH。
- 端口 8765 被占用：重复启动会自动打开已有页面；如需更换占用程序请自行关闭后重试。
- 模型同步报「目标 mod 没有 xxx_macro.xml」：先在「舰船模块」新增同 id 舰船。
- 模型同步报「资源路径里没有 xxx_data」：导出目录结构不对，需保持 EGO 导出布局。
- 模型同步会清空补全脚本所在目录的 xml：该目录请专用于此流程，勿放其他文件。
